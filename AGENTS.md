# AGENTS.md — Development Rules

## 1. Never Overengineer
- Use existing packages. Don't write custom solutions when a library already does it.
- Prefer reduced code. No unnecessary abstractions, factories, or patterns.

## 2. Never Assume
- If confused or unsure about anything, ASK before implementing.
- Never assume a requirement means something — verify with the user.

## 3. Always Document
- Every change must have detailed log with reasoning and timestamp.
- Comments only when the logic is non-obvious.

## 4. Always Verify Requirements
- Revalidate all requirements at least twice before declaring a job complete.
- Never self-assume a job is done. Cross-check the original spec.
